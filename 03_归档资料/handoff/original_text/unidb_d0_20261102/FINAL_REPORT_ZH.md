## 结论

本配置已经按用户要求安全停止，**没有恢复训练**。停止于 **U45411、4,359,456 次样本呈现**，最终五档各 Val1000 全部完成。强湍流恢复目标未达到：G4 **15.895 dB / SSIM 0.3028 / LPIPS 0.4253**，Input 为 **18.796 dB / 0.4518 / 0.5716**。LPIPS 改善与 PSNR/SSIM 下降同时发生，因此不能把这一轮概括为所有指标都变差，也不能把 LPIPS 改善当成内容忠实恢复成功。

最直接的诊断证据是：在固定的训练来源和验证来源上，微调都降低了“干净图前向加噪状态的一步匹配误差”，却提高了模型自身采样轨迹上的后期误差，最终恢复变差；这一分歧在最早保存的 U500 已明显出现。它比“只因训练不够”或“仅在验证集过拟合”更能解释当前现象。具体的单一设计根因仍未被隔离，不能据此宣称整个 UniDB 架构无效。

**补齐2×2对照后的主要定位：G4的微调退化主要体现在“权重 × 随机SDE路径”的交互中。** 固定50个验证来源、4实例的200图上：

|采样方式|官方初始化U0|最终EMA|微调后的PSNR变化|
|---|---:|---:|---:|
|原生随机SDE|18.008|15.761|−2.246 dB|
|官方mean-ODE，去随机扩散|18.531|18.525|−0.006 dB|

mean-ODE下的微调差值95%来源bootstrap区间为[−0.091, +0.080] dB；随机SDE下为[−2.422, −2.061] dB。微调后额外的“确定性相对随机采样优势”增加 **2.241 dB**，区间[2.045, 2.435]。训练来源上的对应现象一致：SDE下降2.299 dB，mean-ODE只下降0.091 dB。弱档G1在两种采样下均改善，这不是所有强度一起出现的简单整体退化。

因此，不能再只笼统说“loss与PSNR不是同一个指标”：固定一步目标确实改善，但微调后的强湍流反向场沿随机路径产生了更大的输出偏差。两节点使用同样的原生噪声日程和固定种子，**没有调大采样噪声**；改变的是网络权重。训练只约束由GT构造的前向状态的一步均值，没有直接约束这条自身生成的100步随机轨迹。它解释了为什么loss下降与实际恢复变差能够同时出现。这里只定位到功能层面的交互，未证明某一层、某个时间系数或唯一数学根因。

**去掉随机性也没有解决强湍流恢复本身。** 最终mean-ODE验证PSNR18.525仍仅接近Input18.561；固定图仍保留大部分模糊/形变。LPIPS从SDE的0.418变为mean-ODE的0.542（越小越好），显示像素/结构忠实度与感知细节之间的取舍。因此这是一项诊断发现，不能包装为新的恢复成功。

此结论限定于同模拟器、冻结来源和原SDE种子的诊断子集；初始化mean-ODE对照明确为看到最终权重对照后的post-hoc补充。没有进行采样参数搜索、完整mean-ODE Val1000或多采样种子评价，更没有新训练。指标已对两个mean-ODE分支全部1600输出独立CPU重算与核SHA。现有证据支持停止原配方长训、先审查采样/轨迹与质量门；不支持直接断言必须改loss或更换骨干。

## 为什么 loss 降，恢复却变差

### 1. loss 真正在改善的对象，与最终恢复不同

代码核对确认保留官方 ConditionalUNet、桥过程和 **MatchingLoss L1**。每张训练图独立抽 t=1..99，由干净图 x0 和退化条件 y 构造前向状态 x_t；loss 比较预测的一步反向均值与已知 x0 的最优一步均值。它**不直接计算 100 步最终图像对 x0 的误差**。

推理从 y 出发，连续使用模型自身生成的状态并逐步加入原生 SDE 随机扩散。后续输入可能偏离训练时的干净图前向状态。因此，前向状态上的局部目标改善，并不保证模型对自身偏差状态的纠正能力改善。标准扩散训练也使用此类局部目标；此处证据说明该目标在本次迁移配置里未转化为忠实恢复，不能仅凭这一逻辑就断定原生 loss 实现有错误。

### 2. 固定状态复测确认，分歧在 U500 已出现，训练来源上也存在

### 5. 已核查的工程与评价解释

- **指标/文件错误：** U0 与最终各5000份输出、输入 SHA 全核；独立重算每张 PSNR/SSIM/MAE，所有差为0；全部 LPIPS 均值重新聚合为0差，未重跑 LPIPS 网络。
- **采样对照复核：** 两个mean-ODE对照合计1600份已保存输出另由纯CPU核SHA并重算PSNR/SSIM/MAE、聚合LPIPS，均与报告一致，零新网络调用。
- **简单裁剪或全局颜色均值：** 对20000份已保存输出做 CPU 敏感性分析。最终 G4 从原始15.895 dB裁剪后仅15.910 dB；借 GT 去均值也仅15.909 dB，不能解释相对 Input 约2.90 dB的差距。GT 去均值仅诊断上界，不是可部署修复。
- **数值路径：** 旧预检 GELU 失败已归档，原数学公式 erf 修复后原容差 PASS。此次再用真实RGB256的U0/最终EMA、四强度、t=1/50/99，共24组前向 CPU/NPU 对照，最大绝对差 **0.00022673607**，均通过原 atol/rtol 容差。未见粗大前向数值错误，但有限前向对照不等于对全部训练梯度与100步误差传播的数学证明。
- **权重/接口：** 官方 SR 文件 SHA、151项 strict load、U0 raw/EMA 与官方逐项同一、数据配对/分割/全量缓存审核、官方 RGB 范围/条件输入与桥参数均已核查。训练与推理均向模型提供退化图条件；没有原生显式 task prompt，也没有本次新增 Adapter。
