# 已有 checkpoint 的泛化曲线诊断

**结果：两项模型在 500→1000 步都呈现明确的后期过拟合：训练指标持续上升，而固定 heldout 的最终 PSNR 下降。**

- T1：同一 train64 从 21.3987 升至 24.1839 dB；heldout32 从 19.5941 降至 18.6084 dB（−0.9858 dB）。
- T2：同一 train64 从 20.4495 升至 23.3164 dB；heldout32 从 19.4644 降至 18.2551 dB（−1.2093 dB）。
- 此区间，两项模型的 32/32 heldout sources 都在“每 source 平均 realization 和 G”后变差，不是少数异常 source 拉低均值。
- 900→1000 仍是相同方向：T1 train +0.1944 / heldout −0.1079 dB；T2 train +0.2345 / heldout −0.0632 dB。
- T2 首次预测与最终预测在 500 步之后均下降；后续递归在全部已测 checkpoint 的 G>1 上进一步降低组均值，G1 首末相同。
- 五个采样 checkpoint 的两项模型，在每个 G 上的最终 heldout 均值都低于输入。早停可以减少这里观测到的损失，但这些 checkpoint 中没有一个证明了正向泛化恢复。

因此，“1000 步还不够，继续训练同样 100 个 source 就能解决”不受当前曲线支持。数据覆盖不足是合理的优先检验对象，但尚未通过 source-scaling 实验隔离其因果贡献；本次没有扩大数据、续训或选择新的部署 checkpoint。

仅补充推理：T1/T2 的 100、500、800、900 步各 256 条 heldout 路径；1000 步及全部训练评估复用。训练更新数为 0，旧实验、checkpoint、数据及冻结 evaluator 均不修改。

训练曲线固定同一 64 starts / 16 clean sources；500/1000 从全 1600 结果中筛出这 64 条。heldout 固定 32 sources × 2 realizations × 4 G = 256 starts。两侧曲线覆盖不同 source，不能把 gap 本身当作数据量的因果证明。

## 解释边界

- 判断“训练继续变好而 heldout 变差”须看各模型自己的时间曲线；不同模型可以呈现不同趋势。
- 如果曲线下降，可确认该采样区间的泛化随训练恶化；不能仅靠本实验把原因唯一归到 100 个 source，也不能排除架构、优化或内容分布因素。
- 如果两侧上升，只说明截至这些 checkpoint 仍在改善；不能保证继续到 2000 会超过输入，更不能宣称收敛。
- 只有 5 个采样 checkpoint，未定位未采样区间的最佳点；本诊断不据 heldout 选择新的 checkpoint 或训练设置。
- 增加 source 的效益仍需控制训练预算的独立 source-scaling 实验，本次未执行。
- 此 heldout32 已被重复查看，用于事后诊断；后续调参后的最终泛化主张需要新的独立测试集。

## 执行与验证

8 组新推理共 2048 starts，推理控制器约 118 秒完成；复用 1152 条既有评估结果，汇总核对 3200 条 per-start 记录、5600 个逐轮指标和 300 个聚合值。训练更新为 0。4 个 own-process guards 正常退出，没有发信号给外部进程。新记录的模型/模拟器状态前后哈希一致，checkpoint 文件哈希前后相同。

实际使用 de36 的 0–3 卡，每卡 own cap 8 GiB / reserve 6 GiB；启动前低算力负载、HBM 安全余量和已有外部延迟基线均通过。共载期间未触发保护，但外部新请求计时样本不足 12 条，无法给出可靠的延迟比，不能声称已量化证明零影响。

结果包不重复传输 NPU 上的预览 FP32 arrays；原始 arrays 保留在 `reports/heldout_curve_20260919_2138/evaluation/` 对应目录。附带 `cached/` 为复用指标的独立副本，旧结果原件保持不变。主图和全部 G 图已逐张检查，无截断或遗漏；G1 首末输出重合被如实显示。
