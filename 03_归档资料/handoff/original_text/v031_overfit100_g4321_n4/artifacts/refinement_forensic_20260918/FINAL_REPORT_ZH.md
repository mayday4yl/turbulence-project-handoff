# V0.31 精修负作用审查

2026-09-18；对象：checkpoint 1000 raw，推理时对 xi 的观测残差精修。

## 结论

**当前精修确实在认真降低它被要求降低的误差，但这个误差不足以代表我们最终想要的恢复质量。** 同一状态下的真实干预和梯度检查已经给出直接证据：更好地重建原观测，能够同时让下一次恢复更差。原始步幅还会放大这种损伤。

这次没有找到足以解释负效的明确实现错误，也没有证据把负效归因于 NPU 算错。不能因此声称 backend 的所有问题均已排除或底层 root cause 已彻底定位。审查验收 PASS 表示测量可信、状态保全通过，**不表示精修效果 PASS**。

建议保留已表现出收益的“不精修递归”作为当前研究主线；将现有观测残差精修列为负面消融。下一版若继续研究精修，必须解决优化目标与后续恢复之间的关系，不能继续把“J 降了”作为精修有效的验收条件。下面把已证实的事实与尚未证实的解释分开。

## 1. 实际审了什么

- 复核已有 7,424 个 refined/unrefined 配对起点和 11,136 条精修记录；没有重做这部分历史实验。
- 独立实现审查，重新运行 23 项原有 CPU 测试、独立 Adam 递推/解析检查，以及 6 项观察器与记录支持测试。
- 新增固定 48 个起点：原 fixed64 的 16 个 source，各取 G4/G3/G2；固定第一预测 clean、原观测和网络 xi，记录原 Adam 的 0/1/5/10/20/40 次状态。
- 相同起点增加 GT-clean 目标对照、真实 xi 对照、真实下一状态对照。GT 只用于诊断。
- 预先指定其中 4 个 source、共 12 个起点，测量局部梯度、真实 Adam 位移、两块 xi 的干预及两个固定小位移比例。

全部真实诊断调用原冻结 solver，采用 FP32、batch1、LR0.01、40 次，未改变科学定义。48/48 与正式 canonical 结果通过既有容差；observer 返回的 best xi 与原 solver 返回逐元素 exact。梯度 12/12 完整通过。四卡诊断于北京时间 01:25 启动、01:32 释放；这只是 NPU 诊断用时，不包括此前代码、历史证据和后续报告审查。

恢复网络 optimizer 更新数为 0。原 87 个冻结文件、1000 checkpoint、正式 workflow/handoff 身份前后一致；正式状态仍为 PAUSED_AT_1000。新增 312 个 FP32 数组共 704,683,008 字节，逐文件 SHA256、形状和 dtype 核验通过，保留在服务器的新诊断目录；未回填历史缺失记录。

## 2. 先区分：递归有收益，现有精修有负效

下表来自原正式 1000 raw 全量结果，每个 G 有 400 个起点。它衡量完整合法 rollout 的最终恢复，不是下面诊断子集的 K2。

| 初始强度 | 不精修递归相对第一次预测 | 加精修相对不精修递归 |
|---|---:|---:|
| G4 | +0.954 dB | −0.540 dB |
| G3 | +0.564 dB | −0.401 dB |
| G2 | +0.208 dB | −0.241 dB |

因此不能把精修失败扩大成“整个递归 idea 没有作用”。当前收益仍是在训练图像上的结果，尚不能代替独立单次恢复基线或未见图像泛化证明。

历史记录还显示，精修并非所有阶段都负效：早期 raw、较早的 EMA 曾获益，后来转负。update100 的参数校准按观测残差改善/耗时选择，并未保证 update1000 的恢复质量最优。

## 3. 为什么 J 降了，恢复却坏了

用人话说，网络预测的 xi 已经参与了“让下一次网络恢复得更好”的联合训练；推理精修却只问“用当前 clean 和 xi 能不能更像原始观测”。这两个问题的答案可以不同。

数学上，固定当前预测 clean 为 c：

`J(xi) = MSE(F(c, xi, G), Y)` —— 精修实际最小化的观测误差。

`D(xi) = MSE(clean_head(S(F(c, xi, G−1), G−1)), C_GT)` —— 我们真正关心的下一次恢复误差。

J 不包含下一次网络调用，也没有直接评价恢复结果。训练的 full-BPTT 则让 xi 接收到后续 clean 损失。**训练学到的状态与只按 J 更新后的状态，并没有自动兼容的保证。** 这不是要求中间态必须等于 GT；中间态的用途仍然是帮助恢复。

新固定 48 起点的同状态对照结果如下。下降比例为各起点相对初值比例的平均，PSNR 是同一 K2 的配对差；各 G 为 16 个 source。

| G | 40 次后 J 平均下降 | 生成下一图到真实弱态的 MSE 平均下降 | 下一次恢复 PSNR 变化 | 恢复变差 |
|---|---:|---:|---:|---:|
| G4 | 85.97% | 72.89% | −0.845 dB | 16/16 |
| G3 | 84.60% | 64.93% | −0.551 dB | 16/16 |
| G2 | 80.84% | 39.37% | −0.346 dB | 16/16 |

这直接说明：“更拟合观测”甚至“更接近真实弱退化图”，在当前系统中都不能保证下一次恢复更好。中间态 MSE 在这里仅用于解释，不能取代恢复指标。

![观测拟合、恢复质量与中间态误差](figures/01_objective_vs_restoration.png)

图中返回状态按 J 选择 best，包含初值。子集损伤与全量均值不同是样本范围不同；子集各行已与正式记录逐一对照通过。

## 4. 不只是“40 次太多”：方向冲突与步幅放大同时存在

在 12 个预先指定起点上，计算同一 xi 处的 ∇J 与 ∇D。它们的普通欧氏梯度余弦全部为负：

| G | 平均 cosine | 负 cosine |
|---|---:|---:|
| G4 | −0.968 | 4/4 |
| G3 | −0.978 | 4/4 |
| G2 | −0.984 | 4/4 |

这说明普通的 −∇J 局部方向与恢复目标强烈冲突。但 Adam 会对坐标重新缩放，**不能把上表直接解释为实际 Adam 对所有样本都在错误方向上移动**。

进一步直接检查实际 Adam 首步位移 δ：

- `δ·∇D > 0` 为 8/12；另外 4/12 的局部预测反而有利。
- 取首步位移的 0.01 倍，实测 8/12 变差、4/12 改善；0.1 倍时 10/12 变差、2/12 改善。
- 原始完整首步在这 12 个样本全部变差；在全部 48 个配对起点中也全部变差。
- 按 J 选 best-after-1 时，有 8/48 因首步 J 未改善而退回原 xi，其余 40/48 恢复变差；到第 5 次及之后的已记录 best，48/48 都变差。

极小位移的 MSE 变化约为 10⁻⁸ 至 10⁻⁶；没有为这些小变化另做重复噪声置信检验，不能把它们当作已确认的部署收益。逐例变化方向与初始梯度预测相符，提供的是局部数值证据。

因此，小步可能减轻损伤，并在部分样本上出现局部改善；但已有结果不支持“只要少跑几次就能普遍获得收益”。本次两个固定比例是方向诊断，不是完整的小 LR 训练/求解轨迹，不能直接宣称哪个新 LR 已通过验收。

两路 xi 的作用也不同。首步的 Zernike-only 替换已产生主要损伤，tilt-only 的平均损伤较小；40-best 时两块单独替换均有负效，合用还有非线性交互。普通梯度余弦主要受 tilt 路径影响，而有限 Adam 首步损伤主要体现在 Zernike 路径，两种测量并不矛盾。不能仅凭块 L2 范数或梯度余弦给出“各占多少百分比”的加法归因。

这里的 ∇J、∇D 是对 xi 的导数，与以前训练时对网络参数 θ 分解 L_C/L_R 的结果不是同一个量。best40 与初始梯度的点积也只是初始点线性投影，不能当作 40 步的完整因果分解。

## 5. 单独把目标里的 clean 换成 GT，没有解决问题

我们从同一 xi 开始，把优化目标中的 c 替换成真实 clean；下一次生成与恢复依然使用原预测 c，避免把真实 clean 直接送给下一网络。

| G | 原目标精修后的 K2 变化 | GT-clean 目标精修后的 K2 变化 | 真实 xi 与预测 clean 配对 |
|---|---:|---:|---:|
| G4 | −0.845 dB | −1.684 dB | −2.442 dB |
| G3 | −0.551 dB | −0.986 dB | −1.516 dB |
| G2 | −0.346 dB | −0.578 dB | −0.928 dB |

GT-clean 分支 48/48 都更差，且每例都比原目标分支更差。这使“只要目标里的 clean 准了，就会自动改善恢复”的解释站不住脚。

但它没有证明 clean 误差补偿完全不存在。GT 目标仍是欠定求解、只跑 40 次，而且求得的 xi 随后与预测 clean 配对；这些对照不是保证最优的 oracle。真实 xi 与有误差的 clean 组合也未必最适合当前网络。

真实弱态直接送入同一网络的变化为 G4 −0.392、G3 −0.175、G2 +0.480 dB，因此也不能说“网络只认自己生成的图，真实物理输入全部无效”。当前证据支持恢复目标与状态干预不兼容，但还不能唯一分离 clean/xi 耦合、网络对输入变化的敏感性和欠定性各自的贡献。

## 6. 排除了哪些直接解释，还有哪些没有排除

| 解释 | 当前判断 |
|---|---|
| Adam 符号写反、少更新一路、返回错参数 | 未发现；独立递推和原 solver 对照通过 |
| 错用当前弱态作观测、G/Y 绑定错误、clean 被偷偷更新 | 未发现；生产入口与诊断对齐、状态检查通过 |
| “继承上一步 xi”才导致问题 | 不是首次负效的必要条件；首 transition 无继承仍受损。后续放大作用未单独定量 |
| 只有第 40 次过度拟合才开始变坏 | 不符合记录；完整第一步已普遍受损。步幅仍有放大作用 |
| 只要把优化目标里的预测 clean 换成 GT，就能解决负效 | 被该目标替换对照否定；下游仍使用预测 clean，因此不能据此排除整个链条中的 clean 误差作用 |
| 原观测残差是恢复质量的可靠替代指标 | 当前 checkpoint/起点上被直接反例否定 |
| NPU backend 是直接原因 | 本次没有支持证据；也不宣称穷尽所有 backend 缺陷 |
| simulator 的坐标约定导致精修失败 | 有继承约定疑点，但数据与全部路径一致，未证实它解释 refined/unrefined 差异；不擅自修改 |

## 7. 下一步建议

**当前最有价值的路线是先保住递归收益，再决定精修是否值得保留。**

1. 以已存在的不精修递归结果作为工作基线，将现有精修作为负面消融。它已经是原协议中的合法评估模式，不需要重写历史结果。
2. 若继续研究精修，另立有限方案，明确它如何保护后续恢复；验收必须包含同起点后续 clean 质量及未参与选择的图像，不能只按 J、真实中间态距离或 optimizer 是否下降来判定。
3. 步幅限制/按块约束可以作为待验证工程化假设，但不是已证实的修复。小步有少量正例，整体均值仍负，单纯缩小 LR 不足以获得当前证据下的普遍保证。
4. 方法层面更值得考虑的是让训练显式面对将要使用的 refinement 干预，或设计能够约束后续恢复损伤的目标；两者都改变科学定义，应先形成新协议和最小可证伪对照，不能直接改当前 V0.31。GT 梯度只用于诊断，不能拿来部署。
5. 递归主线还需要匹配数据与训练预算的单次恢复对照、未见 source 测试，才能判断论文层面的收益。这些没有在今晚自动启动；也没有恢复 1000 之后的训练。

目前可以作出的强结论是：**现有观测残差精修与当前学到的恢复链存在可重复的目标冲突，默认步幅进一步放大负效。** 不能作出的强结论是：某一新精修公式已经有效、整个递归方法失败、某个 backend 唯一根因已定位，或所有超参数下的精修必然无效。
